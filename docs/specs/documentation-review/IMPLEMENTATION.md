## 文档组织

[文档组织与编写规范](../../README.md)统一规定目录职责、新文档放置、提案收敛、索引与网页发布、单源维护和材料归档。站点在开发文档中直接展示该原文；AGENTS.md 和项目 Skill 引用同一规范。

## UI 组件复用

优先检查已安装 Fumadocs 的公开 API，先复用完整布局，再组合组件和样式原语。正文的标题、表格、列表、引用与代码采用 `DocsBody` 及默认 MDX 组件；移除自制正文排版、响应式目录状态、原生折叠和全局 pre 样式。复制页面链接采用库的 `buttonVariants` 与 `useCopyButton`，补充剪贴板失败反馈；此版本提供按钮样式函数，没有独立 Button 组件。

保留的项目逻辑仅包括来源内容适配、构建身份、快照行锚点和 Mermaid 渲染：Fumadocs CodeBlock 提供代码外壳及复制，未提供与本项目快照参数对应的行定位；已安装 UI 包没有导出 Mermaid 渲染组件。行号使用 CSS 伪元素，复制结果保留原始文本。图表源码由库的 Collapsible 与小尺寸 ghost 按钮展开，来源身份由 Accordion 展开，图表错误使用 Callout。Fumadocs 的图片放大组件不提供正文内的自由缩放和平移，因此引入 `react-zoom-pan-pinch` 处理滚轮、拖动、双指和键盘交互；控件仍使用 Fumadocs 按钮样式，没有引入第二套 UI 组件系统。Mermaid 使用 base 主题及显式明暗配色，随站点主题重新渲染；全局初始化和渲染串行执行，避免多图互相覆盖配置。图表默认完整适配正文宽度，直接内联渲染 SVG；滚轮或双指缩放、拖动空白区域平移，方向键平移、加减键缩放、0 键或比例按钮恢复完整显示。文字区域排除拖动平移与双击缩放，保留选择和复制，明暗主题均采用高对比选区。主题切换重新绑定查看组件并复位视图。展开按钮使用同一 Radix 技术栈的 Dialog 原语提供接近全窗口的大视图，Fumadocs 本版本没有公开通用 Dialog 外壳；焦点约束、Esc 关闭和焦点返回由 Radix 负责。弹层沿用缩放、平移、复制和高对比选区；正文保留视图状态，展开期间只在弹层渲染 SVG，避免重复 Mermaid ID 干扰连线和样式。

侧栏工具行通过 `DocsLayout.githubUrl` 固定链接项目 GitHub 仓库；版本号与原生 ThemeSwitch 通过公开 slot 组合在同一行，使用浅色、深色、跟随系统三种模式；跟随系统响应系统配色变化，显式选择保留在浏览器中。构建时读取 Git 版本标签，正式标签上的干净构建显示原版本；超前提交或本地修改显示 `-dev`，无版本标签时显示 `dev`，完整构建描述保留在悬停提示中。版本元数据随来源身份保存，不请求在线最新版本，也不维护独立版本副本。

组件状态由 Diagram 和 DocumentActions 的 autodocs 展示，覆盖有效／无效图表、干净／修改来源及复制失败；交互故事覆盖源码展开、来源展开和复制反馈；五个状态已在静态 Storybook 浏览器中执行检查，未出现页面异常。

## Validation

项目导航调整后已通过 `docs:check`、十一份材料静态构建、11 项来源单测、独立 Storybook 构建和三种尺寸的 24 项 Playwright 检查。浏览器覆盖正文与来源快照、行定位、Mermaid、图表源码、章节链接、窄屏图表及键盘缩放、明暗主题和页面宽度；目录分组的一致控件、祖先展开、当前页、键盘折叠和移动导航关闭；来源信息键盘展开、页面链接复制与源码复制逐字一致；真实架构图默认适配、正文内按钮和滚轮缩放、鼠标及方向键平移、复位、文字选词复制、明暗切换及 SVG 主题同步。

图表交互检查覆盖三种宽度下的缩放、平移、复位、键盘与文字复制，并增加 393×852 触控场景中的双指缩放及单指平移；31 项浏览器检查通过，覆盖大视图尺寸、SVG ID 唯一性、关闭与焦点返回，以及侧栏 GitHub 图标、构建版本和明暗切换；另外两个桌面项目按设计跳过触控专用用例。冻结锁文件安装、严格文档检查、来源单测、独立静态构建和 Storybook 构建通过。

仓库 `bun run check`、`bun run test:repo`、Go 测试、Spec 合同与 10 项文档检查通过。Skill 测试包含要求干净提交的发布打包保护，应在候选提交上运行；不绕过该保护。

修正前的追溯交互测试不作为当前验收证据。人工验收检查文档本身的阅读和定位。负责人在实际浏览系统架构并反馈导航、图表及源码入口后表示“先这样吧，推进到 PR 合并”；该确认接受当时的阅读呈现。其后新增的文档组织规范经严格构建及页面检查，并由负责人单独确认“可以，纳入 PR 并继续”。最终提交仍须绑定回归与 PR 证据。

### 构建测量

测量入口为 `DOCS_PORT=<leased-port> bun docs-site/content/measure.ts`，结果保存在忽略的 `.generated/performance.json`。测量冷构建、完整预渲染及单文档开发重编译，并记录环境和实际输入摘要。不预设性能阈值。

2026-11-17 的一次实测环境为 macOS arm64、Apple M4、Bun 1.4.4、Node 24.12.0，依赖已安装。来源基准为 `10ab9c88c24db039cc9d4f39d630f50538dd4f97`，包含本次修正中的本地修改；实际输入摘要为 `062b01280335c863df5c50968ca8cbc5e1e04267a625bec7a1adc56b6dda72db`。该摘要描述测量时输入，不冒充之后更新实现记录的最终候选。

| 项目 | 实测 | 方法 |
| --- | --- | --- |
| 冷构建 | 5,631 ms | 清除子项目 `.source/` 和 `build/` 后完整构建。 |
| 完整预渲染 | 4,588 ms | 对相同来源重复静态构建。 |
| 单文档开发重编译 | 969 ms | 原文写入至生成模块经 Vite 转换的响应；探针随后恢复。 |

开发循环没有构建 Go。这是环境绑定的单次观察，不能推断其他机器或全量文档的性能。

## 修复覆盖

正式审查指出修改中非站内文档的章节链接未定位，以及预校验将所有编译异常降级为单篇错误。适配器现将中文、重复标题与显式 HTML 锚点解析为快照行号，并诊断缺失锚点；预校验仅隔离已识别的 MDX、YAML 与元数据语法错误，未知编译异常向上传播。新增单测覆盖实际行定位、代码块内伪锚点、语法隔离与编译器故障传播，11 项来源单测通过。

文档验证作业固定使用 Ubuntu 24.04，以匹配锁定的 Playwright；保留原有 PR/Main gate 名称和必需检查。
