# 文档站主题背景

项目需要独立维护的文档站，让用户理解如何使用项目，让开发者理解设计。首期先完成设计材料，再建设站点，以本主题作为真实内容验证表达与构建。

实现过程中误将提高设计阅读效率扩展为独立需求追溯工作台。项目负责人澄清：本期目标是文档展示；独立审阅页面、关联异常演示和额外关联维护成本均退出范围。未来文档审阅功能另行设计。

Fumadocs 选型、单源正文、独立构建、来源身份与后续管理台接入边界继续有效。当前要求以 [SPEC](SPEC.md) 为准。

站点信息架构同样面向项目读者，而非建设任务。“本次设计”式材料列表已退出主导航，首页和导航区分开始使用与开发文档，文档站自身材料属于开发文档下的具体主题。最初接入既有项目概览、CLI 与系统架构，当时不要求同时完成全量文档迁移。

项目负责人随后要求完整整理全项目文档并确保网页正常显示。范围包括全仓库盘点与分层发布、项目级 PRODUCT 与按需主题 PRD、任务指南、跨目录接入和全站阅读验收。Markdown 是默认格式，MDX 是可选的表达方式。当前要求以 SPEC 为准，最小站点的证据不替代扩展需求的验收。
