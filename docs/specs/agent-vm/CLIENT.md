# Agent VM 客户端设计与审查

本文说明 `agent-vm` 客户端的职责、功能和依赖，供设计审查使用。现有实现、设计要求与待审查事项分别陈述；待审查事项不代表已经实现或获准部署。客户端代码直接由 Bun 执行，不要求它位于 Git 仓库中。

## 职责

客户端是一次性请求与连接工具。它解析命令和连接配置，向控制端提交明确意图，验证响应，保存必要的本地连接与重试材料，并调用本机工具连接来宾。命令结束后不驻留，不自动续租，也不运行后台保活。

| 能力 | 客户端负责 | 控制端负责 |
| --- | --- | --- |
| 生命周期 | 表达 acquire、renew、release、destroy、restart、resize 意图，携带请求身份 | 准入、租约、镜像绑定、实例操作、资源核算与持久状态 |
| 查询 | 请求并展示状态，验证响应身份 | 产生权威的实例、租约、容量与诊断事实 |
| 端口 | 提交精确的端口映射请求 | 分配和回收映射，验证原生资源身份 |
| 来宾连接 | 管理本地私钥，消费可信端点和 host key，调用 SSH | 提供对应任务和代次的可信连接材料 |
| 文件传输 | 调用 SSH、SCP 或 rsync；同步只替换工具拥有的源目录 | 提供连接能力；不替用户猜测租约结束后的数据可恢复性 |
| 失败恢复 | 保留原 operation ID、generation 和请求，查询结果；不把超时当失败重做 | 幂等处理、原生执行日志、恢复与清理的最终判断 |
| 发布部署 | 不提供公共自更新、远端安装或部署命令 | 独立发布工具与部署控制器负责，不由生命周期客户端承担 |

客户端不得直接访问 Incus、PVE、控制端数据库或调度器。`admin` 命令只是受权限约束的请求入口，不构成第二套控制面，也不自动获得维护授权。

## 功能分组

| 分组 | 命令或行为 |
| --- | --- |
| 本地信息与配置 | `help`、`version`、`config init`、`config list`、`config host add`、`config host set-default`、`config project bind` |
| 控制请求 | `doctor`、`status`、生命周期命令、`port` 与 `admin` 命令 |
| 来宾访问 | `ssh-info`、`ssh`、`exec` |
| 文件传输 | `upload`、`download`、`export`、`sync` |

普通控制请求只需要客户端运行时、连接配置及该传输的认证材料。HTTPS 控制请求不应依赖本机 OpenSSH；来宾 SSH 与文件传输仍使用独立的 SSH 连接。获取控制接口的 Token 不等同于获得任意来宾命令的授权。

## 依赖审查

| 依赖 | 当前用途 | 应限定的边界 |
| --- | --- | --- |
| Bun | TypeScript 执行、TOML、HTTP、子进程与文件操作 | 客户端运行时；不要求从源码构建后才能查询状态 |
| OpenSSH | SSH 控制传输、生成密钥、连接来宾、SCP | 使用对应功能时需要，不应成为纯 HTTPS 查询前置条件 |
| rsync | 源码同步的数据传输 | 只属于同步功能 |
| Git | 自动按项目 origin 选择主机；同步选择受跟踪及未忽略文件 | 不得用于证明客户端自身身份，不应成为核心命令依赖；现有项目绑定和同步的替代接口仍待审查 |
| `bun:ffi` 与系统原生库 | 本地状态锁、字节路径访问及同步原子提交 | 按功能检查，不应把同步平台要求扩散到帮助、版本和纯查询 |
| `Bun.build` | 将来宾同步动作打包到内存 | 只属于同步功能 |
| 来宾 Bun、rsync、GNU timeout、原子文件系统能力 | 执行受限的来宾源码事务 | 来宾同步前检查，不应成为控制端健康查询的前提 |
| `client-release.json` | 当前请求前校验本地文件并取得协议兼容信息 | 发布产物校验与运行时通信应解耦，详见下节 |

现有 `sync` 明确使用 Git 选择项目文件；这不是客户端自身必须安装在 Git 仓库内的理由。将来是否保留 Git 感知的同步模式、增加普通目录模式或拆分辅助工具，需要独立审查，本文不把任何一种方案视为已接受。

## 发布信息与运行时通信

当前实现由 `loadRelease()` 读取 `client-release.json`，检查文件哈希和权限，再从其 `client_view` 取得兼容规则。所有控制请求和版本命令受到这条依赖影响。当前源码入口旁缺少清单会返回 `manifest_missing`；补回完全匹配的正式清单只能恢复该安装状态，不能解决职责耦合。

清单包含发布版本、源码修订、协议能力以及客户端文件摘要。它不是连接配置或认证凭据。发布工具可以用它验证产物完整性；与代码同目录的无独立信任根清单本身不能证明代码可信。

已确定的设计约束是：客户端运行不要求 Git，不要求客户端位于仓库中，不通过运行 Git 查询获得身份。缺少版本来源不能伪造成已验证发布；协议兼容仍须由明确规则验证。

待审查的解耦方向是：把协议号、命令能力和兼容范围作为源码内的固定合同；连接配置选择传输；发布工具从同一合同生成发布信息；普通命令不再读取发布清单或校验自身源码。未注入构建身份时如实显示未知或开发身份，不阻断运行。现有协议的 `release_id` 校验限制需明确兼容处理，不能偷偷填入伪造提交、降低 schema 校验或据此要求安装 Git。

## 本地状态与故障边界

私钥、可信 host key、SSH 配置、会话代次和操作日志属于客户端必要状态。它们不代替控制端权威状态；请求超时或响应丢失时，本地必须保留不确定结果，不能换 operation ID 重放原生动作。

以下是代码审计和无远端写入探针确认的现有行为，尚未在本文对应的文档整理中修复。风险描述不是已经发生远端误操作的证明。

| 问题 | 实现证据 | 需要明确的设计要求 |
| --- | --- | --- |
| 主机之间共用本地会话路径 | `Client.sessionDir()` 只散列 session；相同 session、operation ID 在不同主机得到相同路径 | 状态、密钥与重试日志应绑定控制目标，迁移不能误用旧状态 |
| 恢复写入丢失主机字段 | `persistRecoveryState()` 和 `reconcileServerState()` 重建状态时未保留 host 字段 | 恢复必须保持原目标，不能随默认主机改变 |
| 主机切换残留配置 | `applyHostSelection()` 只覆写存在的可选字段；切换后旧 socket 等值仍保留 | 每次连接从独立、完整的目标配置产生，不继承其他目标的残留 |
| SSH 配置没有兑现 | `identity_file` 和 `known_hosts` 被解析到环境，但控制 SSH 参数没有消费 | 支持的配置应实际生效，且保持严格 host key 校验 |
| 核心命令隐式探测 Git | `resolveHost()` 在默认主机前调用 `projectRemote()`，后者运行同步 Git 子进程且无超时 | 核心命令不得要求 Git；自动项目发现的去留、显式绑定方式需要确认 |

## 审查与后续实现的验收边界

- 无 `.git`、无 Git 可执行程序、无发布清单的客户端分发目录可以执行帮助、版本和配置明确的控制请求；未知版本不阻断协议检查。
- 不兼容协议、schema、语义版本和响应身份仍被拒绝；超时结果仍保持不确定，不能伪造成功或绕过 operation ID 与 generation。
- 不同控制目标的相同 session 不互相覆盖；恢复与目标切换保持连接身份；旧状态如何迁移必须有明确规则和回归证据。
- 每类命令只检查自身需要的工具；源码同步的文件筛选与安全事务单独验证。
- 发布产物仍可以独立校验哈希、权限与来源；发布校验失败不能被解释为控制端或来宾故障。

这些条目用于审查修复范围，不表示当前实现已经通过。实现和发布方案须在职责及兼容边界确认后制定；文档整理不授权控制面部署或默认镜像变更。
