# Agent VM 客户端与控制端通信协议

本文是 protocol 4 的中文阅读入口，说明客户端与控制端共同承担的通信约束。命令行参数见[客户端 CLI 接口](cli.md)，HTTPS 的认证、权限及状态码见[Agent API](agent-api.md)，发布身份与产物校验见[产品发布与部署合同](release.md)。

现有详细条款仍有部分位于客户端 CLI 文档，以下链接明确其位置；在逐条迁移和校验之前，不删除原条款或改变其语义。本文不为未实现的客户端解耦方案增加新的协议字段。

## 请求身份

| 字段 | 含义 |
| --- | --- |
| `protocol` | 双方支持的协议号，目前为 4 |
| `action` | 控制动作，不是任意 CLI、shell 或 Incus 命令 |
| `session_id` | 会话目标与归属标记，不是认证凭据；无会话动作按合同省略 |
| `generation` | 本次动作绑定的租约或实例代次，不能由客户端自行重置以绕过冲突 |
| `operation_id` | 变更意图的幂等身份；不确定结果重试必须保留原值 |
| `compatibility` | 当前动作的请求 schema、语义版本和可接受响应范围 |

客户端和控制端各自验证合同，不能因为 JSON 能解析就推断兼容。未知动作、错误协议、超出范围的 schema 或语义版本必须在产生影响前拒绝。

现有兼容字段 `release_id` 接受源码修订或历史标识 `legacy-protocol-4`。这是协议当前的格式约束，不意味着客户端运行必须访问 Git；如何消除运行时对发布身份的强依赖属于[客户端设计审查](../CLIENT.md#发布信息与运行时通信)。不能把协议号、清单格式、产品版本和 Git 修订混为一个版本。

## 响应与结果确认

成功响应包含 `ok`、`protocol`、`server_time`、`action`、会话与操作身份、`outcome`、`result` 和响应 schema 信息，可包含结构化 `warnings`。客户端必须核对请求中已提供的身份字段，再终结本地操作日志。

错误响应使用结构化 `error`。可信的拒绝与结果不确定不同：传输超时、响应截断、身份不匹配或持久状态提交未知，都不能被解释为“远端没有执行”。客户端只接受一个匹配请求的错误响应，不能把无关 stderr 当作控制结果。

stdout 承载正常 JSON 或命令声明的数据流；stderr 承载诊断。`export` 的 tar 流不能混入诊断。日志和响应不得泄露 Token、私钥、认证头或不相关的私有部署材料。

详细响应字段、错误分类、诊断上限及历史兼容行为见[请求与响应条款](cli.md#request-与-response)。

## 传输与认证

| 通道 | 边界 |
| --- | --- |
| HTTPS 控制请求 | 固定 `POST /agent/v1/control`，使用机器 Token 和 TLS 校验；不接受浏览器 cookie、任意控制路由或转发身份头 |
| SSH 控制请求 | 已配置的控制主机通过固定 Go request adapter 访问受保护 UDS；不是远端任意 shell 运维授权 |
| 来宾 SSH | 使用控制端给出的任务端点、代次和可信 host key，以及本地私钥；与控制传输认证分开 |

两种控制传输使用同一 protocol 4，不各自拥有生命周期权威。认证成功也不代替动作权限、租约、代次和原生资源身份检查。Token 的 `agent:sync` 只允许取得连接信息，不单独授权任意 SSH 命令或文件传输。

传输的详细兼容窗口见[Agent API 传输条款](cli.md#agent-api-transport-兼容性)，Token 权限以 [Agent API](agent-api.md) 为准。浏览器的 `/api/v1` 管理接口是独立接口，不是 CLI 输出包装器。

## 幂等、恢复与权威状态

相同操作重试必须保留原请求、operation ID 和 generation。新意图才使用新 ID；客户端不能在原意图结果未知时用新 ID 重做。控制端的持久日志和原生执行证据决定最终结果，本地缓存不能代替它们。

诊断请求只读取证据，不自动恢复或部署。reconciliation 的默认预览不创建操作意图；只有明确的 apply 请求按相应权限和维护条件执行。精确会话恢复不能降级成全局恢复，也不能扩大到其他租约。

详细约束见[精确会话恢复](cli.md#精确-session-reconciliation)、[回收与重试](cli.md#回收与重试行为)及[部署控制器合同](deployment-controller.md)。控制端生命周期、容量和调度规则以 [SPEC](../SPEC.md) 为准，不由客户端重新实现。
