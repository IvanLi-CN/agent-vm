# 客户端运行依赖与镜像选择修复方案

本文整理客户端发布清单阻断和单会话镜像选择两个问题的需求与建议方案，作为实施边界。方案已经确认；本文不表示实现完成，不授权发布、现网迁移或部署。

## 问题与范围

| 问题 | 已核对的行为 | 修复目标 |
| --- | --- | --- |
| 缺少发布清单就不能运行 | `client.ts` 在发送控制请求和选择传输前调用 `loadRelease()`；版本和同步入口也依赖该函数，缺文件返回 `manifest_missing` | 核心命令不读取发布清单，不依赖 Git、仓库目录或本机构建步骤 |
| 客户端不能选择镜像 | CLI 没有镜像参数；控制端新建任务时选择默认镜像，已有任务固定原指纹 | 新建时可显式选择镜像，并提供普通客户端的只读发现入口 |

此前补回与正式版本完全匹配的清单属于临时恢复。它没有消除运行时耦合；历史机器配置和镜像指纹也不构成当前环境的事实。此次不修改全局客户端或真实主机。

范围包括客户端、控制协议、镜像目录、操作日志及相关安装/发布工具的职责衔接。客户端主机状态隔离、SSH 配置兑现、同步功能重构等其他审计项独立处理；本次只消除核心命令的隐式 Git 依赖，不顺带改写同步文件筛选语义。

## 已确认的设计选择

- `acquire --image <名称或完整指纹>`；省略时保留默认镜像行为。
- 活动实例或缓存已绑定镜像时，显式选择不同镜像必须报错并保留原状态；相同镜像允许按原规则复用。换镜像须由用户显式销毁后重建。
- 新客户端保留旧控制端原有命令的兼容性；显式选镜像遇到不支持的旧端必须失败，不能退回默认镜像。
- 增加普通客户端 `image list`，提供受认证、只读的可创建镜像目录，不赋予镜像导入、默认切换、名称改绑、退役或删除权限。
- 镜像名称采用独立且唯一的字段，不把允许重复的展示标签直接当作身份。
- 管理员可显式将名称改绑到新指纹；已有会话与进行中的操作保持原指纹。已有会话再次指定已改绑的名称时，按解析后的指纹判定冲突。
- 现有镜像从既有名称迁移，重名在数据库迁移中追加自然序号，不要求管理员逐一补名。

领域术语见 [GLOSSARY.md](../../../GLOSSARY.md)。会话镜像固定延续 [ADR 0041](../../adr/0041-agent-vm-session-pinned-image-identity.md) 的既有边界；新增名称与协议来源解耦的架构取舍，在整体确认后再记录 ADR 并同步长期 Spec。

## 发布清单阻断的建议方案

### 运行时与发布工具分工

协议号、动作集合、请求结构和响应兼容范围由源码中的协议合同声明，发布构建从同一份声明生成清单，避免维护两套能力表。运行时只使用该合同，不因清单缺失、损坏或与源码不匹配而改换运行路径；安装与完整性校验工具负责报告这些发布材料错误。

`help`、`version` 和配置命令保持本地可用。`doctor`、`status`、生命周期和同步控制请求不再通过 `loadRelease()` 取得能力。连接方式来自连接配置；HTTP 控制请求不因缺少发布清单而要求 SSH。移除核心命令自动探测 Git origin 的步骤，保留显式主机、环境指定、默认主机和显式项目标识的选择能力；依赖自动 Git 发现的旧配置须获得明确迁移说明，不能猜测连接目标。

版本来源作为信息展示：源码默认身份为开发/未知，正式分发可由发布工具注入源码常量，但不要求用户执行构建。未知来源不能声称已验证发布；普通命令不散列自身源码，也不通过 Git 查询安装身份。

发布工具继续校验完整包、哈希、权限和来源。安装器须在激活前校验候选内容，通过暂存与切换避免混用文件；不因移除运行时清单读取而删除安装中断哨兵及恢复材料。控制请求可检查明确的安装未完成标记并报告本地安装错误，但不读取清单或散列自身源码；本地帮助和版本仍可用于排障。混合安装的校验属于安装完整性职责，不伪装成控制端故障。

### 兼容身份

现有 Go 控制端要求请求的 `release_id` 为源码修订或 `legacy-protocol-4`，同时严格验证请求与响应窗口。建议无注入来源的客户端使用既有的 `legacy-protocol-4` 互操作标识，并仍发送完整能力声明；该标识不代表已验证发布，也不省略能力协商。正式构建可以发送注入的真实修订。

这是兼容已有服务端的过渡表示，不伪造 SHA，不把 SemVer 填入 SHA 字段，也不要求运行 Git。服务端响应的既有发布身份格式保持兼容；协议能力检查继续独立于双方是否同一产品版本。后续若引入专门的未知来源字段，应独立设计迁移，不把它作为解除当前阻断的前提。

## 镜像选择的建议方案

### 命令与职责

```text
agent-vm image list --host <host>
agent-vm acquire --host <host> --session-id <session> --image ubuntu-rust
agent-vm acquire --host <host> --session-id <session> --image <完整指纹>
```

这些命令尚未实现。客户端只提交选择意图；控制端负责名称解析、镜像登记状态、完整性、适用性和创建权限检查。普通请求不得传任意下载 URL、主机路径或 Incus 操作，也不自动导入镜像或修改共享默认镜像。

`image list` 不要求会话，仅返回调用者可创建的镜像名称、完整指纹、架构和默认标记；不暴露导入来源、部署路径、凭据或引用会话。使用普通客户端认证边界，不借用管理台管理员授权；本次沿用既有创建授权，不引入按镜像划分的新权限体系。没有可用镜像时返回空列表；查询失败不能伪装成空目录。

### 名称与迁移

名称在同一控制端镜像目录内唯一，展示标签继续保留。建议使用独立名称映射记录，让名称改绑只改变目录引用；旧镜像记录及其现存会话引用保留。完整指纹始终可以直接指定；64 位十六进制选择按指纹解释，名称不占用这种形式，不支持有歧义的指纹前缀。

迁移保留现有非空名称；同名组按稳定顺序（创建时间、完整指纹）分配原名及 `-2`、`-3` 等自然序号，先预留所有已有名称，再为冲突项分配，避免覆盖原本就叫 `ubuntu-2` 的镜像。缺少标签的历史记录使用可追溯的生成名称；非法或超长名称的转换及后缀空间必须有确定规则。迁移保存旧标签到新名称的对应关系，结果可检查，重试不得重复追加后缀。

名称改绑只经管理员显式操作，沿用审计和比较后执行机制；普通 acquire 不创建或抢占名称。改绑后原镜像即使不再有名称，也保留指纹身份和引用，不能因此删除仍被会话使用的镜像。

### 固定选择与幂等

新建操作首次被接受时，控制端在一致的状态边界内解析名称或默认值，验证目标，持久保存选择意图和解析后的完整指纹，再执行原生创建。相同 operation ID 的恢复读取原解析结果，不能因名称改绑或默认镜像变化重新选镜像；请求摘要不同仍按幂等冲突拒绝。

已有活动会话或缓存省略 `--image` 时，继续使用原绑定，不重新读取默认镜像。显式选择同一指纹可复用；选择不同指纹报镜像冲突，不启动替代实例、不清理缓存、不增加一套隐式换镜像流程。缺失、退役、完整性不通过或不适用的镜像保持既有拒绝规则；本次不放宽缓存恢复检查。

显式选择、默认切换、名称改绑、退役和删除须与任务及进行中操作的镜像引用保持一致。目录查询不是创建时的保证，创建事务必须再次验证；不能因为先前列表显示可用就跳过状态检查。

### 协议兼容

旧控制端可能忽略额外请求字段，因此不能单靠增加 `image` 字段。显式镜像选择必须使用能区分该语义的请求能力/语义修订，使旧端在产生效果前拒绝；新服务端保留不选镜像请求的旧窗口。镜像目录查询使用独立只读动作，旧端返回不支持，不影响既有状态查询。

无论服务器如何失败，客户端不得移除 `--image` 后重试，不得把显式选择转换成默认创建。镜像名、完整指纹和操作身份必须纳入日志与响应核对，成功结果明确报告实际绑定的指纹。

## 实现顺序与验收

1. 先抽取唯一的运行时协议合同，拆开版本展示、能力协商和发布校验；覆盖无 Git、无仓库、无清单的本地及控制请求。
2. 增加名称目录与幂等迁移，以及管理员名称维护和普通客户端只读目录；保留镜像指纹及默认设置。
3. 在控制端落地单操作镜像解析、引用、冲突及恢复规则，并加入能拒绝旧端静默忽略的协议修订。
4. 增加 CLI 参数与目录命令，同步协议、CLI、发布合同及相关测试；验证新旧客户端和控制端组合。
5. 经独立交付授权发布和部署，先升级控制端，再使用显式镜像选择。迁移和名称管理入口必须随该功能一起可用，不能要求手工修改数据库。

| 场景 | 必须证明的结果 |
| --- | --- |
| 无 Git、无 `.git`、无清单 | 帮助、版本及有明确配置的控制请求可用；来源未知如实展示 |
| 清单错误与协议错误 | 运行不读取清单；安装校验仍拒绝坏包；不兼容协议和身份错误仍拒绝 |
| 名称、指纹、默认创建 | 均解析到预期指纹；显式未知镜像失败且不创建默认实例 |
| 同名迁移与已有后缀 | 唯一、确定、可重入，原标签和任务指纹不丢失 |
| 名称改绑或默认变化后重试 | 同一操作沿用首次持久化的指纹，恢复不重选 |
| 活动或缓存会话选另一镜像 | 冲突报错，实例、数据、租约及缓存不因冲突被改写 |
| 新客户端显式选镜像访问旧端 | 在原生副作用前明确失败；原命令继续兼容 |
| 权限与并发 | 普通目录查询不获得管理权限；退役、删除及改绑竞态不产生未核验创建 |

## 实施状态

本方案已确认，运行时解耦、名称目录、协议与管理台功能正在实现，验收以当前候选证据为准。每份镜像最多一个名称；目标已有其他名称时必须先显式清除，不能隐式覆盖。

管理台与管理 API 同时提供名称设置、清除和改绑；普通目录返回可空的单个 `name`。名称与指纹双向唯一，清除名称不会删除镜像或改变会话绑定。
