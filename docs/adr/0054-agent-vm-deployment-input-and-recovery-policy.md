# Agent VM 部署输入与状态恢复材料

本文记录部署候选输入、部署控制服务命名和状态恢复材料保留的已接受决策；长期行为合同以 [Agent VM 产品发布与部署合同](../specs/agent-vm/contracts/release.md) 为准。

## 决策

Agent VM 的两个服务端二进制是 `agent-vm-server` 和 `agent-vm-deploy`。`agent-vm-deploy serve` 是位于蓝绿槽位之外、长期运行的部署控制服务；`agent-vm-deploy update` 是正式运维入口。`agent-vm-deployd.service`、`deployd.sock`、`deployd.json` 和 `internal/deployd` 只作为历史兼容标识保留，不作为当前组件名称。

正式部署采用完整的蓝绿事务。默认情况下，目标 Agent VM 控制宿主按 release metadata 获取与自身架构匹配的候选；指定文件部署是同一事务的受控输入模式，允许运维者手动上传正式完整包。可另指定一个与包内 `agent-vm-server` 字节完全一致的文件。两种输入都必须通过 manifest、来源修订、摘要、架构、权限、槽位、健康和部署阶段校验；手动上传不产生新的产物类型，也不授权直接编辑槽位、`active` 指针或控制器主权。

业务状态由 rqlite 作为唯一权威。部署备份使用经过验证的状态恢复点，恢复点包含 rqlite 快照、覆盖边界、来源身份和校验元数据；复制 SQLite 文件不构成状态恢复点，也不构成回退数据库。legacy SQLite 只作为一次性迁移源材料保留，迁移完成、目标摘要验证并满足保留期后才能清理。

同一 rqlite 业务状态权威最多保留三个已验证状态恢复点，按恢复点而不是文件计数。最新两个恢复点始终保留；最旧的第三个恢复点仅在年龄至少三十天且没有有效 lease、进行中的切换、当前回退目标或未完成部署事务时可删除。全部恢复材料的实际文件大小合计不得超过 1 GiB；没有可删除材料且预算不足时返回 `backup_storage_exhausted`，拒绝新的备份、激活或回退，不自动删除最新两个恢复点。

## 后果

部署控制服务的本机 SQLite 只记录部署操作、阶段和证据，不承载业务状态；文档和操作指引使用“Agent VM 控制宿主”“部署控制服务”“部署事务”“状态恢复点”这些统一术语。旧 unit、socket、配置和内部包路径可以继续被历史完整包读取，但不会重新引入旧的独立部署组件或新的发布入口。
