# ADR 0055：root SSH 请求与槽位身份分离

状态：已接受。

## 背景

主服务降权后，现有 root SSH 请求适配器仍以 root 连接槽位。当前及历史服务均以 Unix 对端 UID 保护业务请求；部署健康查询可以通过，普通业务请求却会被拒绝。修改当前服务的 root 白名单不能解决历史版本回退，而且会把部署握手与普通业务授权混在一起。

## 决定

保留两个发布二进制与原 protocol 4。安装器启用 root 专用 `control.sock`，由 systemd 按请求运行 `agent-vm-deploy request-relay`。入口仅接受 root Unix 对端和固定业务协议路由，不接收调用方提供的目标。它从活跃路由选定固定槽位，根据真实 socket 所有者采用 root 或主服务账户身份，再连接业务服务。root 只在已明确支持的历史 root 槽迁移期作为业务连接身份；新账户槽和历史版本降权回退均使用主服务 UID。

root 调度进程只执行自身受保护的程序描述符，不以 root 执行槽位中可由部署账户替换的程序。请求正文、operation ID、generation、响应和退出码保持原样，不加入自动重放、业务逻辑或第二份状态。两项常驻服务保持非 root；该适配器仅在请求期间存在。

安装与账户迁移在候选启动前启用入口，连接资料改用固定 `control.sock`。原固定请求二进制和已发布历史包保持不变。Caddy、部署握手和业务协议入口各自保持现有职责。

## 取舍

按请求增加一次 systemd 启动和身份转发开销，换取旧包无需重构且回退可用。它不增加常驻守护进程、数据库查询或通用提权入口。请求大小、运行时限及并发数量有界；对端、路径、槽位或身份无法确认时拒绝，传输错误不自动重发。

不采用放宽主服务 root 业务白名单的做法，因为旧版无法获得同样修复；不采用可由常驻账户修改的 root 包装脚本、通用 sudo 或可传任意目标的代理。

## 验证

原生验收覆盖历史 root 槽、候选降权槽及历史版本降权回退的普通 root SSH 请求，同时保留网页、登录和业务探针。负向验证覆盖非 root 对端、非固定路由、不受支持的 socket 身份和失败请求不重放。数据库和部署角色仍由原有业务与蓝绿事务合同管理。
