# ADR 0056：VM 保留与租约区间

状态：已接受。

## 背景

现有到期调度在任务为 `active` 或 `preparing`、且租约截止时间为空或已过时，主动关闭访问、停止来宾并保留缓存。首租固定 30 分钟，显式续租固定增加 15 分钟，剩余上限 2 小时；长时间构建、跨阶段审查和等待外部反馈的任务只能在多次续租之间生存，调度器、控制器重启或维护补偿都可能先于操作者结束工作环境。

管理台的销毁确认只有通用警示，不区分普通 VM 和需要保护的工作环境。操作者可能在未注意租约状态的情况下销毁仍在使用的 VM，而 Agent 也没有正式命令表达“保留此 VM，不要因到期自动关机”。

## 决定

VM 保留是独立于租约的持久保护状态，只在任务处于 `active` 时生效；`preparing`、`cached`、`closing`、`deleting` 和 `failed` 必须拒绝保留。保留记录必填理由、保留起始时间，并保留执行 pin 时的 `lease_expires_at` 作为冻结证据。该时间不再推进，也不触发生命周期变更；到期调度、维护补偿和重启恢复必须跳过 pinned 任务。停止的缓存仍按既有 24 小时 age-GC 回收，保留不适用于 cached。保留写入 additive `task_holds` 表，不重写 canonical `tasks` schema；旧权威启动时创建该表，状态能力以 `vm-hold@1` 表达。

保留期间允许 `restart`、`resize`、`port add`、`port remove`、SSH 和执行；拒绝 `renew` 与 `release`，要求先取消保留。`destroy` 仍然允许，但销毁预览和二次确认必须明确显示该 VM 处于保留状态、保留理由和冻结的截止时间。若截止时间已过但任务尚未进入 `closing` 或 `deleting`，允许以代次条件更新执行 pin，避免与到期清理的时间窗竞争；已经开始的清理不可被 pin 回滚。

取消保留必须清除当前保留记录，并以当前时刻加配置的首租默认时长重新计算截止时间，再按从当前时刻计算的配置上限封顶；不得恢复冻结的旧截止时间。pin 和 unpin 都进入操作 journal，管理台动作同时进入管理操作与审计；当前保留理由只有一份，历史由 journal 和审计保存。

首次租期与续期改为显式区间。`acquire` 可以携带 5 分钟至 6 小时的显式首租时长；未指定时继续使用配置默认值。`renew` 可以携带 30 分钟至 6 小时的增加量；未指定时使用配置默认值，结果截止时间以当前截止时间为基准增加，并按从当前时刻计算的上限封顶。配置默认值调整为首次 30 分钟、续期 30 分钟、剩余上限 6 小时；部署可以调低上限，显式请求不得超过该部署的上限。所有区间必须在原生影响前校验，旧控制端必须在副作用前拒绝不支持的字段或动作。

协议 4 以增量字段表达 `lease_state` 和保留信息；pinned 时 `effective_lease` 继续为真，表示会话槽位和操作权可用，时间租约语义由 `lease_state=pinned` 表达，避免未升级客户端把受保护 VM 误判为过期资源。管理 API 增加 `lease.state=pinned`、保留元数据和相应的允许动作，列表与筛选必须能识别保留状态。新增 `vm-hold@1` 状态能力标记；该标记只记录共享数据库可能包含保留状态。按 [ADR 0057](0057-agent-vm-state-markers-are-informational.md)，标记不再作为启动、激活或回滚的准入条件，降级风险由运维者承担。

保留 VM 的资源预留继续计入准入，到期清理、缓存 age-GC 和容量压力都不得自动回收它；容量不足时必须拒绝新准入，而不是驱逐 pinned VM。只有显式管理员 release 或 destroy 可以结束保留 VM，且仍受各自确认和审计约束。

`agent-vm` skill 必须提供 `pin` 和 `unpin` 命令的操作说明，要求 pin 说明理由，并明确：取消保留的目标不属于当前 agent session 时，必须先取得人类批准。skill 不得把保留描述为后台保活或永久租约。

## 取舍

保留让操作者可以跨长任务保护工作环境，但会长期占用 CPU、内存和磁盘预算，容量紧张时只能拒绝新会话。选择显式 release 前先 unpin，增加一步操作，换取“释放”不会顺带结束受保护 VM。保留到期时间作为冻结证据而不是清空或推到远期，保留可核对的历史但要求 unpin 重新授予租约。

`effective_lease` 在 pinned 时保持为真，是新旧客户端兼容的折中；精确状态由新增 `lease_state` 表达。若逐一把旧客户端改为依赖新字段，会让未升级客户端把 pinned VM 当作可忽略的过期资源。首租下限定为 5 分钟、续期下限定为 30 分钟，避免短租约抖动，同时保留长时间任务的连续工作能力。

不采用“pin 即永久租约”：保留仍是可撤销的显式状态，不能绕过 release、destroy、容量准入或审计。

## 验证

生命周期测试覆盖 pinned 跳过到期与维护补偿、unpin 重新计算截止时间、pinned 期间 renew/release 拒绝、destroy 仍可执行、过期边缘 pin 与已开始清理的竞态拒绝。租约测试覆盖 acquire 与 renew 的上下界、默认值、上限封顶和旧字段拒绝。管理 API 与 Web 测试覆盖 `lease.state=pinned`、列表标记与筛选、销毁预览影响项及中英文确认文案。发布验证覆盖 `vm-hold@1` 能力标记、旧包拒绝激活和 rqlite 状态迁移。
