# Agent VM 文档审阅需求收敛说明

## 文档职责

项目负责人已确认首期目标、下列六项选择及整体设计共识，本阶段设计收敛完成。需求与验收记录在 [文档审阅与最小独立站点 Spec](../specs/documentation-review/SPEC.md)，实现覆盖见 [IMPLEMENTATION.md](../specs/documentation-review/IMPLEMENTATION.md)。本文件保留收敛背景和设计材料入口，不重复维护规范正文，也不是站点已经实现的证据。

## 已接受的首期选择

| 选择 | 结论 | 规范来源 |
| --- | --- | --- |
| 首个审阅对象 | 使用文档站自身的需求与设计，按需引用已有架构、Spec 和 ADR；完整项目文档接入后置。 | REQ-DOCS-001 |
| 最小交互能力 | 提供可筛选的需求追溯视图，展开关联设计与验收依据，定位原文和缺少关联的条目。 | REQ-DOCS-005、REQ-DOCS-006 |
| 预览交付 | 独立构建、可复现预览、明确源码身份；正式域名与每个 PR 自动托管预览不作为首期完成条件。 | REQ-DOCS-007 |
| 额外写作成本 | 允许在原始材料中补充少量显式关联，直接读取已有需求编号与验收声明。 | REQ-DOCS-005 |
| 问题预览 | 保留可审阅的问题预览，区分尚未关联与引用损坏／无法解析；完成验收时修复失效引用，说明未关联条目。 | REQ-DOCS-006 |
| 交互价值验收 | 项目负责人使用真实设计走通审阅路径及一个缺少关联的案例，确认减少查找成本；不要求正式计时对比。 | REQ-DOCS-008 |

当前工作先完成需求设计文档，之后才建设最小独立站点。后续的文档嵌入验证、完整项目文档与站点展示、生产及 Demo 完整接入不进入首期验收，边界见 REQ-DOCS-009；阶段背景见 [HISTORY.md](../specs/documentation-review/HISTORY.md)。
