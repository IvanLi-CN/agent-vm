# Agent VM 宽屏布局方案

## 背景

当前管理台的 `.page-stack` 使用 `max-width: 1500px`，导致工作面在更宽视口中停止扩展，右侧出现与任务无关的空白。现有设计基线要求宽屏清单与详情并列、清单占用剩余空间，并没有要求整页保留固定的最大内容宽度。

## 已确认需求

- 宽屏工作面必须占满侧导航以外的可用内容宽度。
- VM 和镜像等清单/详情页面在宽屏保持并列结构；详情栏继续使用约 `384px` 的初始宽度，清单占剩余空间。
- 超宽屏扩展的是工作区和可比较的数据区域，正文段落、说明文字和详情字段继续使用现有组件级可读性约束。
- 现有 `1100px`、`860px` 和 `560px` 断点继续有效，窄屏行为不因宽屏调整而改变。
- 页面整体不得因为超宽屏改动产生横向溢出；只有确有必要的表格区域可以横向滚动。
- 只调整正式管理台清单/详情布局，Demo Inspector 的 `1280px` dock 与 `320px` 栏位规则保持不变。
- 不新增普遍的宽屏测试矩阵，复用现有检查并做针对性回归。

## 设计方案

### 外层工作面

移除 `.page-stack` 的页面级 `max-width: 1500px` 限制，并显式设置 `width: 100%`。全局 `box-sizing: border-box` 使内容宽度包含内边距，工作面继续由 `.work-surface` 负责背景、边界和滚动裁剪。

### 清单与详情

保留 `.split-layout` 的 `minmax(0, 1fr) 384px` 结构；在 `1100px` 以下继续收窄详情栏，在 `860px` 以下退化为单列。清单列使用 `minmax(0, 1fr)`，吸收新增宽度而不推动详情栏或页面产生溢出。

### 可读性约束

不新增全局宽度上限。页面标题说明、长标识、字段值和详情说明继续使用现有组件级换行、截断、复制和字符宽度规则，避免用整页宽度上限替代内容设计。

### Demo Inspector

Demo Inspector 的 `min-width: 1280px` 页面级 dock 规则保持不变。宽屏 dock 继续占用独立的 `320px` 栏位，不能覆盖正式页面；普通管理台工作面铺满宽度与 Inspector 的 dock 规则相互独立。

## 验收与验证

- 代码检查确认 `.page-stack` 不再设置页面级最大宽度，宽屏工作面可占满剩余区域。
- 现有清单/详情断点、移动导航、触控尺寸和表格局部滚动规则保持不变。
- 运行仓库已有的前端检查与测试，不增加新的普遍宽屏测试用例或设备矩阵。
- 实际视觉验收仍以 `DESIGN.md` 和 Web Demo Inspector 合同规定的既有视口为依据；本方案只修正超宽屏空间利用，不改变视口覆盖承诺。

## 取舍

页面级 `max-width` 可以让窄内容保持集中，但会在超宽屏留下未承载任务的空白，也会限制清单的比较空间。移除这一限制后，布局规则直接遵循“清单占剩余空间”；文本阅读约束下沉到具体组件，兼顾超宽屏的数据比较效率和正文可读性。
