# Agent VM 管理台视觉研究

本研究只细化实施前的设计提案。用户已选择“检修工作台”，具体色板与尺寸等待审阅；没有授权产品代码、部署或程序截图。

## Data and jobs

1. 对象为既有 Agent 会话 VM，身份、generation 与会话归属必须可核对。
2. 租约有有效期，释放会撤销访问并停止；不能简化为普通关机。
3. VM 固定不可变镜像身份，默认镜像与已有环境使用的镜像需要区分。
4. 资源数值带 vCPU、GiB、时长等单位；未知与真实零值不同。
5. 来源健康与更新时间伴随数据，不能以一个健康分数概括。
6. 镜像有来源、验证阶段、版本与引用；默认或有引用时阻止删除。
7. 操作有持久身份、阶段、执行者与原因，断线后仍可查询。
8. 维护者需要检查与处理故障，实际使用频率和现网规模尚未测量。
9. 先按常规室内照明的桌面浏览器提出浅色方案；设备承诺与界面语言仍未定。
10. 产品特征来自会话、租约、固定镜像、generation 与操作记录的关联，不添加通用 Incus 管理入口。

没有为现网捏造数据集。后续界面验证使用标明合成来源的样例，计数从同一组行数据计算，重复出现的事实共用一个值。

## Questions and actions

| 界面 | 首先回答的问题 | 对应任务 |
| --- | --- | --- |
| 概览 | 当前可否承接新需求，什么需要检查？ | 查看准入依据与故障对象。 |
| VM 清单 | 哪个会话的环境需要维护？ | 筛选并选择 VM。 |
| 选中 VM | 它属于谁、依据什么状态、维护将影响什么？ | 核对身份、原因与受控动作。 |
| 镜像 | 哪个版本可用于新会话，哪些引用阻止删除？ | 导入、检查验证与引用、设置默认。 |
| 操作与审计 | 刚才的操作到了哪一步，由谁为何提交？ | 按持久操作 ID 恢复查询。 |

“检查与操作并列”是首个验证面的主任务，不为了视觉模板新增趋势图、统计卡或一键重启。某日最需注意的事项由实际状态得出，不在设计文案中预设一台真实故障 VM。

## Direction selection

脚本以 `--app --kind devtools --screens overview,list,detail,settings --options 3` 给出三个方向；未预设主题或已有品牌配色。

- `framed-sheet`：推荐。灰白 L 形框架与白色工作面区分导航和任务，并能容纳清单与选中详情。
- `achromatic-ledger`：可读性强，但以数字账本为重心，对本产品的对象检查与受控动作没有额外优势。
- `data-terminal`：适合持续监控；本次没有夜间使用证据，也不以市场行情式数据扫描为主任务，保留为备选。

采用 `framed-sheet`，seed `1399279798`，未重抽。原始表保存在 [direction.json](direction.json)。提案色值与尺寸在 [DESIGN.md](../DESIGN.md) 维护，本文不重复定义。

选择的产品特征是为标识使用 IBM Plex Mono，并在选中对象的上下文呈现“会话—VM—固定镜像—当前操作”的真实关联。这是可读字段与链接的关系，不是装饰性的拓扑图，也不替代后端 ownership 判断。导航与选择保持中性，数据与焦点采用深青蓝。

## Application to the brief

保持用户已选择的清单与详情并列结构。库中 detail 没有预设图案，按该方向的表格、字段和表单规则组织。库中的 getting-started、usage tray、日期范围、导出、通知、help/AI 等只在真实产品任务需要时存在；不照搬为必选功能，也不填充不存在的历史数据。

宽屏布局初始算式为：窗口 1440px = 侧导航 228px + 工作面左右内边距 48px + 清单 748px + 间距 24px + 详情 384px + 右侧外留白 8px。此算式只是首个验证尺寸的设计约束，不是浏览器实测结果；内容不能承载时折叠布局。

字体沿用方向表中的 IBM Plex Sans 与仅用于标识的 IBM Plex Mono，中文使用系统无衬线回退。正式字体需要本地资源与加载检查，当前未下载、打包或声称已经渲染。
