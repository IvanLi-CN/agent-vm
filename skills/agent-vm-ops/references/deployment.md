# Native deployment boundary

Install the matching client, Go control service, compatibility bridge and systemd assets from one checked-out Agent Toolkit revision. Record the revision and file checksums in protected operations records; do not create an installed-source fork.

If the control environment must be rebuilt or recovered, preserve the state and container data and follow the [topology and recovery runbook](../../../docs/specs/agent-vm/OPERATIONS.md) before replacing files. This deployment reference does not identify the host below CT109 or provide a host rebuild procedure.

| Surface | Deployment input |
| --- | --- |
| Control service | `/opt/agent-vm-native/bin/agent-vm-control`, started by `agent-vm-native.service` |
| Compatibility bridge | `/opt/agent-vm-native/agent_vm_control_bridge.ts`; format-1 releases may retain the legacy Bun controller |
| Control interpreter | Go binary for format 2; root-owned `/usr/local/bin/bun` remains required only for the format-1 Bun release and client package |
| Configuration | root-owned JSON at `/etc/agent-vm-native/config.json` |
| Web configuration | root-owned, `agent-vm-web`-group-readable JSON at `/etc/agent-vm-native/web.json` when management is enabled |
| Durable state | configured local state database and lock directory |
| Native units | `agent-vm-native.service` and the optional `agent-vm-web.service` for format 4; format-1 timer units remain only during compatibility support |
| Local client | complete eight-file Bun package and dependency-hashed `client-release.json`; protected session state under the operator's chosen XDG paths |

The deployment supplies the control alias, Incus project/profile/image, network ACL, control address, guest address pool, host port range, storage path, state database and timer directory through a copied or derived configuration. `config.json.example` is a generic schema/template, not deployment evidence; for the locked deployment policy the installed configuration must set `memory_budget_mib=32768`, `memory_overcommit_ratio=2` and `cpu_startup_pressure_full_avg10_percent=50`. The latter is a startup-schedulability threshold, not a logical CPU ceiling. Placeholder values must be replaced before installation; missing or invalid values fail closed.

When management is enabled, create the dedicated `agent-vm-web` system group before starting the units. Install the Web configuration as `root:agent-vm-web` with mode `0640`, and keep the containing directory at `root:agent-vm-web` mode `0750`. The Web unit reapplies these fixed metadata permissions at startup; it does not grant the Web UID access to the primary control configuration, SQLite state or generic Incus administration. The native unit runs as root with `agent-vm-web` as its effective group so its dedicated authority socket is `root:agent-vm-web` mode `0660` inside a `root:agent-vm-web` mode `0750` runtime directory.

The control service and compatibility request adapter read the same canonical path, `/etc/agent-vm-native/config.json`. Deployment selects the project, image, network, address pool, port range, storage, state database and ACL by installing a protected JSON at that path; alternate runtime config paths are intentionally unsupported. The Go service owns expiry, reconciliation, retry and age-GC scheduling from SQLite deadlines; `timer_dir` is retained only for format-1 compatibility and historical records. Static release-unit verification always uses `/etc/systemd/system`.

Before any mutation, inspect the actual Incus identities, proxy permission, ACL ownership, guest isolation, local filesystem capacity, service readiness, UDS peer policy and protocol versions. Keep credentials and connection material outside source. The protected UDS is an internal control boundary, not a public gateway.

Prepare and verify the pinned guest image separately. Confirm fresh guests generate distinct host keys, reach readiness and expose only the configured services. Verify expiry, exact mapping cleanup, cache reclamation, capacity pressure and generation handling with isolated resources; do not use production operations as a migration gate.

## Control-plane publication

A control-plane release is a logical compatibility unit containing the local client, the Go control service or legacy bridge, systemd assets, release metadata, and exact artifact checksums. It excludes deployment configuration, credentials, connection material, state databases and WAL/journals, locks, Incus container data, and guest images. The release manifest declares protocol, source revision, artifact integrity, target/toolchain where applicable, and per-operation request/response/semantic compatibility in each supported direction.

The public manifest, wrapper, publisher, and failure-state contract is [the Agent VM control-plane release contract](../../../docs/specs/agent-vm/contracts/release.md). Use the repository scripts only with owner-provided deployment inputs; do not put those inputs in the repository.

Publication is manual and operator-owned. It resolves an explicit source revision, builds and checks the manifest locally, uploads exact candidates to a private staging area through the configured control SSH entry, and verifies remote owner, mode, syntax, checksum, and unit contents before activation. The deploy identity may invoke a narrowly scoped root-owned wrapper for the protected artifact and systemd paths; it must not gain PVE, host, Incus project-policy, guest, extra SSH, HTTP, or gateway access. Do not publish through the public `agent-vm` CLI or a VM guest.

The remote control release is activated and health-checked before the local client is changed. The fixed wrapper installs the complete Bun client package, the format-selected Go binary or bridge, the dependency-hashed sidecar, release manifest and systemd assets only at its protected targets. A compatible older client may continue using supported actions with a structured warning; an unsupported action, incompatible protocol/schema/semantic change, invalid transport or unverified checksum fails before side effects. Compatible evolution preserves protocol 4; a breaking change may require an explicit coordinated update. Unattended control-plane updates are disabled by default.

For remote script or unit changes, enter admission drain before activation. The wrapper holds the fixed `/run/agent-vm-native/release-activation.fence` until activation or rollback completes; control-plane drain exit rechecks that fence under `admission.lock`, so admission cannot reopen between the drain check and pointer replacement. Drain blocks new acquisition and restart admission, keeps status/retrieval/release and expiry/reconciliation/cache-cleanup timers available, and never force-kills in-flight operations. Wait for pending operations and task transitions to converge, atomically activate the candidates, run health/reconciliation/timer checks, and exit drain only after success. A pre-activation failure leaves the current release untouched. A post-activation health failure permits one bounded rollback to the previous verified release; a failed rollback keeps admission drained and never rewrites state, generations, or uncertain operations. Retain at least the current and previous verified releases with their manifests and checksums.

Daily requests never edit Incus project policy. Keep release manifests, run records, protected recovery copies, and live infrastructure evidence outside the public repository.

The active format-2 runtime contains the Go binary, fixed Bun client package, bridge, sidecar, manifest and `agent-vm-native.service`; the old expiry/reconcile units are retired only after startup reconciliation is ready. Activation snapshots and removes legacy `agent_vm.py` and `agent_vm_control.py` only when present at their former fixed targets; a failed activation restores their prior bytes, owner and mode with the entire fixed package. Unrelated operator files and retained release directories are not cleanup targets. A historical Python-only control path is not a fallback for either format.

The generic format-1 sequence is `python3 skills/agent-vm-ops/scripts/agent_vm_release.py build --source-root <source> --output <bundle>`, local `verify`, then `publish`; format 2 uses `bun skills/agent-vm-ops/scripts/build_go_release.ts --source-revision <revision> --target <linux/amd64|linux/arm64> --output <bundle>` and the same protected wrapper transaction. The optional legacy `--wrapper` argument, when retained by an existing invocation, must equal `/usr/local/sbin/agent-vm-release-wrapper`; no publisher override is accepted for the Go binary, bridge or socket. `rollback` is a separate operator action bound to a transaction and release identity; its bundle restores the matching eight-file client package and control artifacts before drain exit. Local installation requires Bun for the client package, a bounded staged `version` self-check, a private complete-package recovery record and exclusive lock. The sidecar is installed last; clients fail closed while recovery is pending, and interrupted installation restores the entire previous package. See the release contract for fixed modes, exact owned paths and hash-validated recovery. The format-2 client invokes the Go `request` adapter over SSH, preserving protocol 4, bounded stdin/stdout/stderr and action-specific timeouts. The wrapper's fixed command set is the only remote activation interface.

## Observability boundary

The dashboard and its provisioning source are deployment-owned. Use the [public observability contract](../../../docs/specs/agent-vm/contracts/observability.md) for metric semantics, but keep the Grafana JSON, Prometheus scrape target, collector path and datasource identity in the deployment repository. The Go service publishes fixed read-only snapshots and a protected relay reads them without triggering sampling; capacity, inventory and filesystem textfiles have independent freshness and health. Verify the deployment configuration's 32768-MiB memory base, 2x memory ratio and 50 percent CPU startup-pressure threshold before publishing the corresponding dashboard lines. Export CT-local CPU PSI and the startup-pressure observation separately from logical CPU admission; do not treat a Grafana database export or an Incus project limit of `-1` as an authoritative native admission metric.

## Runtime maintenance boundary

The Go service performs health checks, reconciliation, lease expiry, bounded retry, cache age-GC and observation sampling inside the configured control environment. SSH is only a request compatibility entry and direct internal scheduler calls continue when SSH or HTTP request adapters are unavailable. These operations must not require access to the PVE host or use `pct exec` as a substitute for the native control path. The one-time split of a CT root filesystem from its Incus data pool, including moving `/var/lib/incus/images` because it is used for transient image unpacking, is an operator-owned infrastructure migration and is documented separately in [the CT root/data split solution](../../../docs/solutions/agent-vm/ct-root-data-split.md).
